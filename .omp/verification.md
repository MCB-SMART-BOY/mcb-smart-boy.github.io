# 验证流程与证据边界

本文件面向维护者与 AI 协作者：规定怎样验证改动，并区分已有证据与待验证项目。下面的清单不是通过记录。界面契约见 [design.md](design.md)，实现边界见 [architecture.md](architecture.md)，工具与发布操作见 [maintenance.md](maintenance.md)。

## 1. 选择与改动匹配的证明

| 改动 | 首先要证明什么 | 不能用什么代替 |
|---|---|---|
| 页面、样式、动效、焦点 | 在真实浏览器观察改动后的页面和操作结果 | 只检查 CSS 还在、编译成功或 SSR HTML |
| 分享等异步交互 | 真实能力路径与受控失败、取消、过期请求路径分别验证 | 把替身返回成功当成系统分享成功 |
| 内容、路径、排序 | 实际目录、文章、导航与导出网址一致 | 写死文章数或逐行比较源码字符串 |
| 路由或 hydration | 同次 SSR/WASM 产物下完成导航、刷新与交互 | 仅运行 Rust 单元测试 |
| 纯文档 | 对照源码与配置，核对链接、命令、章节归属和历史证据 | 为文档或 UI 外观增加永久测试 |
| 发布配置 | parse/lint、构建及授权后的真实平台验收 | 本地静态预览 |

先做对应行为证明，再运行项目检查，最后运行独立通用质量门。一个检查失败不应阻断其他独立检查的诊断；未运行、缺工具、失败必须分别报告，不能写成通过。

## 2. 准备正确的运行对象

### 开发路径

```sh
cargo xtask build
cargo run --locked
```

在 `http://127.0.0.1:3000` 检查本地 SSR 与浏览器接管。持续开发可改用 `cargo xtask dev`。普通 `cargo run --locked` 不构建浏览器资源，不能用新 SSR 配旧 `run/site` 检验 UI；只导出 `run/pages` 也不会更新开发资源。

### 静态路径

```sh
cargo xtask export
uv run python -m http.server 4173 --bind 127.0.0.1 --directory run/pages
```

这是本地验收用的可选静态服务，另需 `uv` 和其可用解释器，不是网站运行或构建依赖。访问 `http://127.0.0.1:4173/`；端口占用时选择空闲回环端口并记录。只使用本次成功导出的文件，不回退到旧产物。

- 等待 hydration 标志、字体加载、目标状态或动画事件；不以固定 sleep 判断完成。
- 普通静态服务器的未知路径错误页不是本站错误页证据。单独访问 `/404.html` 检查本站内容；未知路由 HTTP 404 由 SSR 测试与部署平台分别验收。
- 浏览器替身、能力覆盖与媒体模拟只作用于测试标签，结束后清理并关闭标签。临时服务器用完停止。
- 修改 Leptos 版本、组件边界或资源命名后，开发与静态两条路径都必须验证。源码中保留动效代码不等于实际页面已加载它。

## 3. 界面与交互验收矩阵

### 首页、导航与布局

| 场景 | 观察结果 |
|---|---|
| 正文顺序 | `home → focus → open-source → background → codeflow → notes → about`；关于后仅保留收尾 GitHub 入口和 footer |
| 导航一致性 | 桌面展开、折叠、移动与无脚本后备导航顺序一致；不再链接经历或荣誉锚点 |
| 分区定位 | 逐个点击、自然向下及反向滚动；侧栏与面包屑匹配，到底为关于；普通滚动不改 URL 或焦点 |
| 跨页锚点 | 从文章进入 `/#about`，完整页面加载后正确定位；关于中的返回顶部入口回到首页 |
| 响应式 | 至少检查 1440×1000、1024×900、390×844、320×800；列数取决于真实正文容器宽度，不能只按窗口宽度推断 |
| 教育卡片 | 与项目卡片的底色、边框、圆角、间距及字体规则一致；三列、两列、单列切换，无旧式左侧大空栏 |
| 社团介绍 | 中英文长段落不撑破布局；Logo 完整；内容表达交流方向，不新增活动成果 |
| 语言与主题 | 中英界面、浅深主题、长英文标签、偏好恢复；文章原文不被当作英文翻译 |
| 窄屏与焦点 | 无横向溢出或顶栏遮挡；键盘目标可见；移动抽屉点击内容锚点后关闭并聚焦目标 |

### 原有视觉效果

- [ ] 自然滚动时逐节进入、缩退，反向滚动恢复；长章节中段清晰。检查真实 `opacity` / `transform` 和画面，而非仅查 CSS 文本。
- [ ] 外层锚点位置稳定，内部 `.landing-motion` 动画不使导航高亮漂移；键盘可见焦点不被淡化。
- [ ] 折叠按钮飞到折叠后 Logo 的实际中心，抵达后才出现双水波。快速展开取消旧帧与装饰。
- [ ] 首次恢复折叠偏好、悬停与聚焦不会触发水波；减少动态偏好关闭装饰动效并保持全文可见。
- [ ] 项目／教育和关注卡片保留各自既有悬停反馈；两种主题下背景网格、首页轨道等几何装饰仍可见。

### 分享

| 路径 | 必须观察的结果 |
|---|---|
| 入口 | 44px 图标按钮有明确名称、用途说明与键盘可访问描述；未接管时不可用 |
| 无 Web Share、剪贴板可用 | 真实点击后提示“链接已复制，可以粘贴分享”；通过原生 Clipboard 读取核对完整 URL，包括 query/hash |
| Web Share 成功 | 只说明“已调用系统分享”，不宣称收件人收到；有原生环境时另验系统面板 |
| 延迟完成 | 立即显示进行中，禁用重复点击，无关闭按钮；真实 API 仍在点击回调中调用 |
| 用户取消 | `AbortError` 显示“已取消分享”，不自动复制、不当作失败记录 |
| 权限／能力失败 | 展示手动复制面板和当前真实链接，不伪装成功；链接输入获得焦点并选中 |
| 结束反馈 | 成功、取消、获取链接失败的提示可关闭；Escape 与关闭按钮返回分享按钮焦点，成功反馈不抢焦点 |
| 旧请求失效 | pending 时改变路由或 hash，再完成旧 promise；旧反馈不得重新出现 |
| 连续操作 | 关闭后再次分享正常；新操作先清除旧面板，不能让它遮住同步获取链接失败 |
| 可访问性 | 常驻唯一 live region 位于隐藏卡片之外；可见重复文案隐藏于可访问性树，关闭按钮仍可访问 |
| 小屏 | 320px/390px、两语言两主题下提示完整可见、不挤压其他顶栏操作 |

受控 promise、`AbortError`、`NotAllowedError` 只证明应用处理逻辑。没有系统分享能力或读屏环境时，分别标记“原生分享面板未实测”“读屏播报未实测”；不能用 DOM 属性声称已经听到正确播报。URL 获取失败若难以安全注入，记录该分支仅做控制流审查，不伪造运行证据。

### 代码块标识与复制

- [ ] 语言标识和复制图标嵌在代码框右上边框，不新增工具栏行；两语言、两主题及目标视口下不遮第一行、不撑破页面，长标签截断但复制按钮仍可见。
- [ ] 真实点击、Enter 和 Space 复制对应 `code.textContent`；逐字符核对缩进、空行、Unicode 和末尾换行，不混入标签、图标或提示。
- [ ] 受控能力缺失、属性访问抛错、同步抛错、非 Promise 返回、拒绝及延迟完成分别验证；进行中不能重复点击，成功变为勾号，失败失焦后仍可见且能重试。
- [ ] 切换文章、目录及 Back/Forward 后没有重复／残留控件；旧文章的 pending promise 完成不会改变新文章状态。
- [ ] 每块只有一个常驻 live region；无脚本及 WASM 失败时保留语言和完整代码、不显示无效按钮；WASM 延迟完成后每块只挂载一次。读屏播报需另行实测。
- [ ] 共享 Clipboard 实现变更后回归分享：完整 query/hash URL、取消不复制、失败保留手动链接；替身成功不能当作原生剪贴板证据。

### 阅读区、内容与历史

- [ ] 从当前生成索引发现全部规范页面；不沿用旧记录中的“九页”或“十一个页面”作为固定清单。
- [ ] 首屏有完整正文；目录只列实际直接子项，阅读树包含完整内容；最近记录最多三篇，日期倒序、同日路径升序，不影响归档的 weight 顺序。
- [ ] 新增、移动、改标题或排序后，目录页、左树、面包屑、父级入口、正文内容链接和导出路径一致。具体作者检查见 [content-format.md](content-format.md#verify)。
- [ ] 左树当前页准确，深链展开祖先；目录整行导航，再点当前目录只折叠／展开且不增加历史。修饰键保留浏览器原义。
- [ ] 主导航长列表先滚到边界才进入归档；只有内容根且树在顶部时向上滚轮可返回首页，文章和深层目录不跳出阅读。
- [ ] 移动树的目录、根入口与面板切换保持抽屉打开；文章和段落关闭抽屉，Escape／关闭按钮返回菜单按钮。
- [ ] 右栏显示时外缘距窗口右侧 16px；1440px、1920px、2560px 及左栏折叠／拖动后距离一致，正文与目录不重叠、页面无横向溢出，主列不超过 1004px、文章不超过 850px。
- [ ] 右栏与紧凑 `details` 目录随工作区宽度切换；跨断点焦点迁移不滚屏、不强制打开详情；快速反向和主动改焦点不会执行旧请求。
- [ ] 段落高亮随真实位置更新，底部选末标题；普通滚动不改 URL、历史或焦点。
- [ ] 深链带 query/hash 刷新、两页往返、多步 Back/Forward、重复 URL、相同完整 URL 去重、replace 均保持正文、地址、面包屑和树一致。
- [ ] 升级路由补丁时执行 `/writing/` → 系统目录 → Rust 目录 → Rust 文章 → Back → Forward → Rust 目录，再检查 Back 的目标；具体缺陷边界见 [architecture.md](architecture.md)。
- [ ] 无 JavaScript、WASM 失败／延迟、非法 cookie、减少动态偏好时验证对应后备；不能让全文因动效初始样式而消失。

## 4. 项目检查与独立质量门

行为证明后，在项目根依次执行：

```sh
cargo xtask check
"$HOME/.omp/agent/validate.sh"
```

后者是本机 OMP Harness 提供的验证器，不随网站仓库分发，不是普通读者运行网站的前置条件。缺少它时项目检查仍可运行，但协作交付要明确通用质量门尚未完成，不能以 `--quick` 代替。

`cargo xtask check` 的实际顺序由 `xtask/src/main.rs::check` 定义：

| Gate | 检查内容 |
|---|---|
| Rust format | workspace 只读格式检查 |
| Rust clippy | `--locked --workspace --all-targets -- -D warnings` |
| WASM hydrate check | 单独检查 hydrate feature 与 `wasm32-unknown-unknown` |
| SSR and WASM build | 构建开发服务与匹配的浏览器资源 |
| Workspace tests | 锁定依赖的 workspace 测试 |
| Static Pages export | release SSR/WASM 与静态导出；检查首页、404、归档根 HTML 非空且为普通文件 |

这三份关键文件的存在检查不是遍历全部页面、浏览器接管或线上状态码的证明。项目 gate 会汇总独立失败。

通用质量门顺序为 Secrets → Format → Lint → Type Check → Build/Eval → Dep Audit → Test。Rust 类型检查由 Clippy/build 覆盖；网站依赖审计不覆盖全局安装的构建工具，已知工具风险见 [maintenance.md](maintenance.md)。部署配置变更另做 actionlint 与 ShellCheck；发布后需单独核对 HTTPS、深链、无尾斜线请求、真实 404、WASM MIME 和资源完整性。
